# TNA-302 bench validation — 2026-09-10

The provisioner identified the 302 on physical port 4 (isolation VLAN 1994),
initially reporting 1.12.3. Its automatic firmware/configuration run passed.
Independent readback confirmed both banks at 1.15.1 rev 55177, bank 1 active,
all 59 original baseline expectations, four populated profiles with matching
keys, matching SNMP, successful standard root authentication, and rejection of
factory and empty passwords.

That was a migration/recovery pass, not factory qualification: the shared
301/302 SM template omitted station profiles, so it depended on existing device
profiles. The first factory attempt confirmed this gap: an exact-model folder
was ignored because the deployed resolver selects the registered family
`TNA-301-302`. That attempt failed at secrets with zero profiles.

fleet station profiles while preserving every other field. Removed the unused
exact-model copies created during this test. This changes the family baseline
for both 301 and 302; only the 302 is being hardware-qualified here, and the 301
still requires its own run. Backups of both deployed family templates are private.
