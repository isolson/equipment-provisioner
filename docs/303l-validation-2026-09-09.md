## Findings and deployed changes

The original installed handler preserved the management-VLAN flags, but its
ownership table classified station profiles as mode-only. Its secrets method
handled SNMP but ignored the configured station passphrase. The host has a
station passphrase matching all four profiles in the supplied known-good
15:26:19 export.

The tested and deployed revision uses the Tachyon profile ownership, profile-secret
application, wireless readback, and supporting ownership-contract changes from
evidence revision `432274f`. It adds bounded config-read recovery and verifies
secret readback without logging values. A failed write, missing profiles, or
unavailable/mismatched readback must remain a failure.

The deployed 303L SM baseline comes from the same evidence revision. Its
schema `version` field is omitted so the deployed handler treats it as a
partial template and merges it with live config, preserving device accounts
and the device's schema version. This compensates for the existing full-export
heuristic, which otherwise mistakes the six-section reduced baseline for a
complete device export. A regression test checks that merge behavior.

The original single-read behavior failed the transient-read regression;
two failure-path tests passed. The first candidate targeted run passed 94 tests.

The first patched automatic retry exposed an additional HTTP 400: firmware
1.15 rejects newly created secured station profiles when their passphrases are
absent from the initial config POST. A controlled request with the existing host
key supplied in memory returned HTTP 200; all four profiles and their keys
matched on readback. The final handler prepares these secret-owned fields before
the initial POST, while keeping the template secret-free. The later secrets
phase still checks profile keys and SNMP readback explicitly.

Final verification: 83 focused tests passed; the full suite reported 891 passed,
4 skipped, and one pre-existing failure in
`test_mode_endpoint_requires_cambium_ptp_profile`. That Cambium expectation also
fails on the unchanged deployment. An initial subprocess-test dependency gap
was corrected in the isolated test environment. Template lint and the Python
3.9 syntax check passed. All 138 non-secret baseline expectations match the
supplied known-good 15:26:19 export.

## Root credential correction and kiosk recovery

The operator clarified that a fresh root login accepted factory credentials,
then set a temporary bench password. This was not passwordless access. They
reported that everything else looked correct. The earlier 138-field checks
and account-preservation comparison did not verify a deployment root password;
Wi-Fi and SNMP secret success does not cover management authentication.

Inspection found an empty primary host Tachyon password setting and a populated
separate tagged root credential. The handler's pending secret path covered
Wi-Fi and SNMP, not root. Its old password-change fallback also targeted
`system.auth` instead of the observed `system.users` list.

The scoped correction requires a non-default root target from the original host
credential or saved tagged root credential. Login fallback cannot overwrite the
deployment target. The secret phase now includes root password application and
fresh-session authenticated config access. Missing targets, failed writes, and
failed verification block success. Captured config POSTs use MD5-crypt hashes;
the handler generates the device-required representation using OpenSSL stdin,
without placing credentials or hashes in command arguments or logs. It changes
only the root password field and preserves other account fields.

Independent live repair verified that the standard password works, factory and
empty logins are explicitly rejected as authentication failures, and all
non-root-password config fields are unchanged. Factory run 4 subsequently
failed the immediate root-authentication check; this is retained as failed
process evidence. The revised password path waits for exact hash readback and
the authentication reload before the final fresh login.

Factory run 5 started from a captured baseline with zero station profiles and
successful factory login, with automatic provisioning stopped until capture.
Every automatic step then passed. `factory-5-review-summary.json` independently
confirms all 138 baseline fields, all four profile keys, SNMP, preserved
non-password account fields, successful standard-root login/config access, and
explicit authentication rejection of factory and empty passwords. Successful
standard logins between negative probes prevent consecutive failed attempts.
Raw config, port state, reset responses, and service log remain private.

The final source passed 900 full-suite tests with four skips and the same

passed 21 tests, including an additional regression that refuses success when

The final deployment is recorded in `root-password-settle-deployment.json`.
OpenSSL is already installed on the host and is used by the password path.

The kiosk issue was traced to stopped `provisioner-web` and `kiosk-watchdog`
